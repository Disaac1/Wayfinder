Product Requirements Document (PRD)Project: Wayfinder - Archipelago Multiworld Orchestrator1. Objective & User PersonaThe Goal: Reduce the setup time for an Archipelago multiworld session to a 3-click process: Join Lobby $\rightarrow$ Pick Game $\rightarrow$ Click Ready. Eliminate the need for port forwarding, manual YAML editing, and single-host dependency.Target Audience: Casual gamers who want to play multiworlds with friends but get overwhelmed by configuration files, command-line interfaces, and manual patching.2. Core Architecture & Tech StackClient Application: Godot Engine (Desktop executable). Handles the UI, local shell commands, auto-patching, and game launching.Central Matchmaking & State Backend: Node.js with an SQLite database. Handles lobbies, WebSocket real-time updates, YAML compilation, and save-file state management.Networking Protocol: Bundled Cloudflare Tunnels (cloudflared). The host's client spins up a reverse tunnel automatically to expose the local Archipelago server to the lobby without port forwarding.3. Core Functional PillarsPillar A: The Lobby & Generation SystemPlayers join via a simple code, select their game (e.g., Minecraft, Super Metroid, Slay the Spire), and configure settings via dynamic UI toggles instead of raw YAML files.The backend compiles the selections, generates the seed, and distributes the required .multidata and patch files back to the clients.Pillar B: Zero-Config P2P HostingOne player is designated as the Host. Their Godot client silently downloads the Archipelago server, runs it locally, and executes a Cloudflare Tunnel.The tunnel URL is sent to the backend and distributed to all other players. Their clients automatically patch their games and launch with the connection string pre-filled.Pillar C: Distributed Cloud Saves (The Checkout System)Sessions are not bound to a single player's hard drive. The SQLite backend tracks save files.When a player hosts a resumed session, they "check out" the save file (locking it). When they close the server, the Godot client zips the save, uploads it to the backend ("check in"), and unlocks it for future sessions.Includes a "Force Unlock" override in case the active host crashes or disconnects unexpectedly.
